# PiPER H 仅夹爪与完整机械臂：实现、正确性及效率对比

2026-09-30 更新：网页仅夹爪模式默认改为固定笛卡尔末端轨迹，无需完整臂参考。固定轨迹以五次平滑插值生成位姿，解析生成线/角速度和加速度，随任务时长缩放；参考重放保留为可选配对方式。新固定模式实测 16/16 场景通过，回放正常，结果见 `results/gripper_only/fixed_default_web.json`。下文性能数字仍是 2026-09-29 的实际完整臂轨迹配对结果，未与新固定轨迹混合。

实测日期：2026-09-29。完整机械臂仍是默认模式；仅夹爪通过网页选择成功的完整臂参考记录启用，仅支持 Warp GPU。此实现对齐 Physim 的外部驱动末端设置，双指仍为 MuJoCo 刚体关节动力学，没有引入 Physim 的软垫本构。

## 实现与适用范围

- `gripper_only.py` 从同一配置生成模型，移除六轴臂、对应驱动和碰撞排除项，保留夹爪基座、双滑动指、同步约束、夹爪驱动、桌面及自由物体。基座是 mocap 根体，无广义自由度；`nv: 14 → 8`，`nu: 7 → 1`。控制按 `gripper_opening` 名称映射。
- 规定运动通过专用 Warp 步进适配器显式启用；完整臂仍调用原来的 `mjw.step`，核心引擎默认路径不变。适配器限定当前 PiPER 双滑动指、elliptic 接触、implicitfast 积分，拒绝流体力和 flex。它不是任意关节树的通用 prescribed-body API，也没有实现通用传感器、能量统计或回调管线。
- 每步先更新根位姿，再构建运动学、碰撞和约束。在六维接触各行补充规定运动的相对速度和加速度，随后计算手指速度与惯性偏置，最后执行驱动、自由加速度、约束求解和积分。补偿不会被后续约束重建覆盖。
- 对根原点到接触点/指质心的向量 `r`，运输速度为 `v₀ + ω×r`，加速度为 `a₀ + α×r + ω×(ω×r) + 2ω×v_rel`。滑动指惯性偏置增量为该质心加速度在关节轴上的投影乘指质量；滑动指方向不随自身关节变量旋转。角接触行加入 `ω` 和 `α`。接触参考加速度补偿为 `−B·Δv − Δa`，沿用当前接触参数计算阻尼系数。
- 根体反作用不再改变机械臂运动；手指与物体仍动态耦合，因此两种模式不要求逐位相同，报告实际物理指标而非只检查物体没有掉落。

## 参考轨迹与历史

`robot_mode` 默认及旧记录均为 `full_arm`；`gripper_only` 必须提供 `reference_run_id`。后端要求参考是已完成、所有场景通过的 Warp 完整臂记录，逐项核对物体、参数、时序和批量规模。网页复制并锁定这些字段。上传物体使用参考运行自己的网格快照。

`gripper_reference.py` 为每个场景独立读取完整 qpos/qvel，在 GPU 上重建运动学与空间速度。数组形状为 `(worlds, steps, 19)`：世界位置、wxyz 四元数、根原点世界线速度、世界角速度、世界线加速度、世界角加速度。

轨迹按步前时刻记录：第 0 帧使用初始状态，第 k 帧使用参考第 k−1 步的积分后状态。位置和速度来自状态及解析运动学，**加速度采用解析速度的前向差分**，以表示离散步的速度增量；最后一帧沿用前一加速度。它不是对位置二次差分，也不是精确连续时间逆动力学加速度。0.5 ms 离散化和 float32 轨迹会产生小幅物理响应差异。

缓存包含导出版本、参考配置、模型几何/拓扑/惯量哈希、源文件尺寸与修改时刻、实际读取状态的 SHA-256。读取缓存检查签名、形状和类型；损坏元数据会重建。旧历史没有当时模型哈希，因此此处哈希描述当前用于重建的模型，不能追溯证明旧模型版本完全相同；本报告另生成了当前版本的完整臂网页参考。缺失逐场景状态或速度的旧记录会拒绝并要求重跑。

每轮仅夹爪保存 `root_motion.npy`、`reference.json` 及动态状态，trace 内保存对应根位姿。MuJoCo 历史渲染先恢复根位姿，再恢复动态状态。缓存只是准备优化，回放不依赖参考记录继续存在。

## 纯步进对比

RTX 5090 D v2，MuJoCo 3.13.1，Warp 1.15.0；60 mm 方块网格 SDF、双指网格 SDF、257³ 稠密缓存。物理步 0.5 ms、控制 2000 Hz、任务 12 s，每场景 24000 步，接触容量 256、约束容量 1024；完整配置随各组原始 JSON 保存。

两种模式使用相同单步 CUDA graph Python 提交循环，预热 10 步后重置位置、速度、加速度、warmstart、时间、溢出标记及轨迹游标；每组交替测量三次。主计时关闭回放记录、两端 GPU 同步，仅夹爪的 GPU 轨迹注入包含在计时内。建模、稠密缓存、轨迹导出、上传和下载在主计时外，另行报告。

| 场景数 | 完整臂中位数 s（最小–最大） | 仅夹爪中位数 s（最小–最大） | 耗时下降 | 速度比 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 11.016（11.006–11.098） | 10.114（10.080–10.936） | 8.19% | 1.089× |
| 128 | 13.538（13.513–13.581） | 13.155（13.090–13.325） | 2.83% | 1.029× |
| 512 | 17.097（17.038–17.483） | 15.895（15.797–16.170） | 7.03% | 1.076× |
| 1024 | 25.071（21.832–31.176） | 21.117（20.449–22.070） | 15.77% | 1.187× |

1024 场景中完整臂重复波动明显，区间与仅夹爪重叠；该档中位数差异不能解读为稳定保证的加速比例。主机为共享设备，另有约 8.8 GiB 常驻推理进程及桌面进程；测量前后 GPU 空闲，但没有独占/锁频保证。较稳定的 1、128、512 档表明去掉机械臂收益有限，并没有消除 SDF 接触成本。

## 512 场景 GPU 模块分析

每 100 步采样一次，三次重复，每次覆盖 240 个采样点。下表为详细插桩采样的三次均值，单位 ms/批次物理步，运动学类别已减去嵌套碰撞和约束跨度，避免重复相加。SDF 子项属于碰撞，不能再次计入总和。

| 模块 | 完整臂 ms | 仅夹爪 ms |
| --- | ---: | ---: |
| 碰撞（含 SDF） | 0.2415 | 0.2479 |
| 其中 SDF 窄相 | 0.2225 | 0.2352 |
| 运动学与动力学 | 0.2004 | 0.1198 |
| 约束构建 | 0.0937 | 0.1001 |
| 约束求解 | 0.1424 | 0.1486 |
| 积分 | 0.0423 | 0.0397 |
| 其他（含规定运动补偿） | 0.0032 | 0.0161 |
| 总 GPU 步时间 | 0.7234 | 0.6722 |

仅外层事件计时为完整臂 0.7114 ms、仅夹爪 0.6591 ms；详细插桩分别增加 1.69%、1.99%。模块计时只用于解释结构，主性能结论采用无插桩墙钟计时。规定运动注入及补偿归入“其他”，没有被漏计。

主要减少的是运动学与动力学（约 0.2004 → 0.1198 ms，下降 40%）；碰撞、SDF 和求解器没有随六个关节的删除而同步减少。仅夹爪的规定运动补偿增加了一部分成本。这解释了 nv 降低约 43%，总耗时却仅小幅下降。

## 内存、复现与原始数据

补采的 512 场景进程内存快照见 `memory_512.json`：完整臂计时点显存 8156 MiB，仅夹爪计时点 9022 MiB，进程 RSS 高水位均约 3682.5 MiB。该诊断进程同时持有两种模型缓存，但不保留全程验证状态；仅夹爪额外上传约 890.6 MiB 的规定运动数组。它与下述含全程验收的 1024 进程内存口径不同，不能跨档直接比较模型内存收益；补采计时不混入主性能统计。

1024 场景当前进程 RSS 高水位约 11864.7 MiB。计时进程同时持有两种模型及稠密缓存，完整臂计时点显存约 9150 MiB，仅夹爪计时点约 10910 MiB（增加的轨迹张量约 1781 MiB）。这些是进程整体快照，不能用来声称模型独占内存降低。中断前的原始外部采样保存在 `memory_samples.jsonl`，含其他进程 PID，分析时需按其中被测 PID 过滤。轨迹数组存储为 float32，每场景每步 19 个数，512 场景约 890.6 MiB；缓存和每轮回放副本各占一份磁盘空间。
