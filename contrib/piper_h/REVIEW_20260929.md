# 2026-09-29 代码审查与三版本复测

## 审查范围与结论

审查覆盖当前未提交的模型/XML/OBJ、配置、抓取与验证、回放兼容、页面字段、八叉树与稠密查询接入、新增测试和全部性能测量脚本。稠密距离索引、三线性插值、单元梯度系数与物理坐标缩放、双几何坐标变换、默认关闭路径未发现新的公式错误。

发现并修复两个测量工具问题：

1. **短轨迹预热可能越界读取控制数组。** `finger_cost_profile.py` 允许 `--steps 1`，但原预热固定推进 10 步。剖析工具和完整计时函数现在限制预热不超过轨迹长度，空轨迹直接拒绝。使用真正的单步 CUDA graph，三版本分别在 1、2 个环境下完成烟雾测试。
2. **固定姿态碰撞测试可能漏报容量溢出。** 单独调用 `collision()` 不执行物理步末尾的容量检查；仅读取 `overflow` 不够。现在直接检查接触计数和粗筛候选计数，同时保留已有溢出位。批量完整计时的溢出位也改为按位 OR 汇总，避免遗漏同时发生的不同问题。

另外补充稠密基准的参数范围、CUDA 可用性和 NXN 粗筛检查，避免无效参数产生空报告或误标粗筛阶段。稠密碰撞数学实现本轮未改动。

- 性能有效性回归：5 项通过，覆盖独立碰撞的粗筛/接触容量检查及空轨迹拒绝。

- 完整三版本复测先分别执行完整抓取验收，再开始计时；如非有限状态、溢出或最终落点误差超过 5 mm，脚本保存数据后报错退出。

## 复测口径

版本为 `box_octree`（盒体手指＋八叉树物体）、`sdf_octree`（八叉树手指＋八叉树物体）、`sdf_dense`（257³ 稠密手指＋稠密物体，单元梯度系数）。物体均为 60 mm 网格方块，不使用解析方块。

三个版本使用相同控制数组、质量、惯量和物理参数；脚本校验动力学参数及控制数组一致。1 和 512 个环境各执行 24,001 步，每组重复三次并轮换顺序。完整计时包括 CPU 提交、控制更新、GPU 物理步和结束同步，排除编译、上传、缓存构建、graph 捕获、预热与下载。

两个环境数都另测碰撞分项：每 20 步在原 graph 内采样 CUDA events，每版三轮分项、一轮只计碰撞总耗时的校准。分项采用碰撞总时间中位数对应的整轮，阶段不跨轮拼接；校准差异包含运行波动，并非误差上界。

固定姿态测试使用本轮盒体抓取保存的夹紧/搬运状态，三个版本共享相同 qpos/qvel；独立重复 collision，不推进动力学。所有基准都检查容量溢出。

```sh
uv run python contrib/piper_h/three_way_benchmark.py --worlds 1 512 --profile-worlds 1 512 --repeats 3
```

原始数据位于 `results/review_20260929/benchmark.json`，包括版本、源文件 SHA256、配置、所有重复计时、完整抓取验收和逐步剖析采样。`benchmark.snapshots.npz` 保存固定姿态；`gpu_processes.log` 保存测量期间 GPU 进程采样。

## 适用范围

稠密缓存仍需显式启用；每个模型的缓存由所有环境共享，当前约增加 3.01 GiB 显存。构建来源是相同编译八叉树，传感器仍走原生路径。几何修改后须重新构建；切换缓存须重新捕获 graph。低分辨率和格点梯度插值的精度限制见 `DENSE_SDF.md`。

512 环境使用相同初态和控制。本次验证不涵盖随机化场景、多套不同的批量 mesh 数据，或所有棱边/退化接触状态。GPU 进程采样用于记录后台负载，不等价于强制独占设备。
